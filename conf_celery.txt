Celery კონფიგურაცია (Redis-ით)
=============================

1) Python dependency
--------------------
`celery` და `redis` უკვე `requirements.txt`-შია:
pip install -r requirements.txt

2) .env პარამეტრები
-------------------
.env-ში დაამატე:

REDIS_URL=redis://127.0.0.1:6379/0
CELERY_BROKER_URL=redis://127.0.0.1:6379/0
CELERY_RESULT_BACKEND=redis://127.0.0.1:6379/1

# თუ Redis-ზე პაროლი გაქვს:
# REDIS_URL=redis://:YOUR_STRONG_REDIS_PASSWORD@127.0.0.1:6379/0
# CELERY_BROKER_URL=redis://:YOUR_STRONG_REDIS_PASSWORD@127.0.0.1:6379/0
# CELERY_RESULT_BACKEND=redis://:YOUR_STRONG_REDIS_PASSWORD@127.0.0.1:6379/1


3) systemd service Celery-სთვის (რეკომენდებული)
-----------------------------------------------
შექმენი:
sudo nano /etc/systemd/system/ies_shakemap_celery.service

გადაიტანე კონფიგურაცია repository-ის ფაილიდან ies_monitoring_celery.service.

- Worker-ს `--concurrency` არ გადასცე (ან გადაეცი 1): `src/celery_app.py`-ში `worker_concurrency=1`,
  ShakeMap ერთდროულად ერთზეა გათვლილი.
- Unit მხოლოდ `.env`-ს ტვირთავს, ამიტომ `CONDA_EXE` და `SHAKEMAP_CONDA_ENV` `.env`-ში უნდა იყოს.
- Unit-ს აქვს `Requires=redis.service`; Ubuntu-ზე Redis-ის unit ხშირად `redis-server.service`-ია
  (alias `redis.service`) — გადაამოწმე `systemctl status redis`.

4) systemd აქტივაცია
--------------------
sudo systemctl daemon-reload
sudo systemctl enable ies_shakemap_celery
sudo systemctl restart ies_shakemap_celery
sudo systemctl status ies_shakemap_celery

5) ლოგების მონიტორინგი
----------------------
journalctl -u ies_shakemap_celery -f

6) სწრაფი შემოწმება
-------------------
შემოწმება რომ კონფიგურაცია მოქმედია:
python -c "from src.celery_app import celery; print(celery.broker_connection().as_uri())"
